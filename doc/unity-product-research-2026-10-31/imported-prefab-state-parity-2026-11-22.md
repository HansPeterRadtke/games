# New Unity product R&D: Imported Prefab State Parity, 22 November 2026

## User problem and source-grounded demand

Unity's official October 22, 2026 announcement of planned Unity 7 changes notes the switch from Mono to CoreCLR, the removal of the Built-in Render Pipeline, retirement of several rendering/lighting features, and new serialization conditions that will become errors. The official team recommends using **Project Auditor** before upgrading. It warns that future changes might cause additional issues beyond the published list. A genuine Unity publisher/developer comment on November 21 describes around fifteen thousand lines of custom Built-in pipeline shaders needing migration to URP, demonstrating a concrete expensive upgrade burden, **not a willingness to buy our product**. Source: https://discussions.unity.com/t/planned-breaking-changes-in-unity-7-0/1740094 .

Existing **Scene Diff** on the Unity Asset Store explicitly compares **prefab/scene YAML from two source versions**, matching GUIDs/fileIDs and documenting that cross-Editor serialization migrations may create noise. Its current public storefront asks **$35 per seat**, displays **eight favorites**, and has **insufficient ratings**; that is a concrete competing asking price, **not eight paid customers or proof of our projected income**. Existing **RefSafe Pro**, **Release Check Pro** and Unity's own **Project Auditor** already cover broad static missing-reference/project validation. A generic project scanner or a new static Unity 7 migration checklist would duplicate that competition. Sources:

- https://assetstore.unity.com/packages/tools/version-control/scene-diff-reliable-scene-prefab-comparison-389882
- https://assetstore.unity.com/packages/tools/utilities/refsafe-pro-project-validator-cleaner-363422
- https://assetstore.unity.com/packages/tools/utilities/release-check-pro-game-asset-validator-401728

The more defensible distinct purpose is **comparing selected actual loaded prefab values across two installed Unity Editors, using the exact same original `.prefab` and `.meta` bytes**. A byte-identical source is a necessary precondition for attributing any different observable values to the import/Editor behavior. The previously built **Publisher Version Matrix** already proved equality of the source files and importer metadata but did not measure values after native Unity loading. This new product is separate: **HPR Imported Prefab State Parity** uses `PrefabUtility.LoadPrefabContents` in isolated scenes and `UnloadPrefabContents` without saving; it snapshots hierarchy, component inventory and selected fields relevant to 3D/animated prefab compatibility. The official API documentation states LoadPrefabContents loads a prefab into an isolated scene and UnloadPrefabContents releases it without altering the asset. Sources:

- https://docs.unity.com/en-us/engine/7000.0/script-reference/unityeditor/prefabutility/loadprefabcontents
- https://docs.unity.com/en-us/engine/6000.6/script-reference/unityeditor/prefabutility/unloadprefabcontents

## Scope and non-claims

This is **not a general serialization difference engine** and not a claim to support Unity 7 before an actual Unity 7 installation exists. The first original tool captures hierarchy paths, active/tag/layer/static flags, local Transform position/rotation/scale, Renderer material references, Animator controller/avatar references, covered Collider values and Rigidbody settings. All remaining component types are counted explicitly as **unsupported**, and their values are **not** silently treated as verified. Unity's `EditorJsonUtility.ToJson` and `SerializedObject` can access broader fields, but raw object serialization can contain noise or scene-local references; the first product intentionally limits which values it can compare stably across Editors. The exact two-editor comparison returns one of three separate conclusions: changed original inputs (not attributable to Unity), different covered native imported values (review required), or covered values matching (only the declared subset, not full parity). No source file, prefab, project setting or business account is modified.

The tool is built entirely on public first-party Editor APIs, with no network calls or runtime assembly, requires two disposable Unity projects and only actual source assets that the publisher owns. Source content is private with a candidate-only license status. The native QA must use fresh author/export and independent buyer import in both Unity 2022.3.22f1 and 6000.6.8f1, three original first-party animated prefab teaching examples, original `.unitypackage` identity verification, separate synthetic negative controls, exact matched-source checks, readable original GUI screenshots and official Asset Store Tools validation. One passing source test or one Editor success is never a buyer-ready proof.

## Fresh November 22 source checks: real customer pain and limits of this exact product

- A September 10, 2026 Unity developer reports repeated intermittent **nested Canvas prefab child scale becoming zero in the serialized source**, not visible until a later reload; a vendor reply acknowledges recurrence in Unity 6.3 despite a presumed 6.X fix. This is real user pain, but the saved `.prefab` source itself changes: our tool's identical-source gate intentionally blocks attributing it to an Editor cross-import difference, so the present product **does not repair or automatically diagnose** that issue. https://discussions.unity.com/t/the-prefab-scale-values-are-set-to-zero-when-the-prefab-with-a-nested-canvas-is-modified-through-a-script-12312/1736242
- Unity Issue Tracker `UUM-139664` documents an earlier 2026 lost Prefab Variant reference when a nested component serializes a prefab class; Unity lists the issue as **fixed** in 6000.6.0a6 and other supported streams. That problem involves a custom component's serialized field, which **this first version does not inspect**, so do not advertise coverage or claim to reproduce a resolved engine bug. https://issuetracker.unity.com/issues/19770/the-reference-to-a-prefab-variant-is-lost-on-instantiation-when-it-is-serialized-in-a-parents-component
- A September 5 developer thread about apparently disappearing serialized values was resolved by correct Unity Editor dirty/save handling. This is a workflow issue, not evidence that different Editor versions import identical bytes differently. https://discussions.unity.com/t/values-of-serialized-field-set-at-editor-time-disappear-randomly/1735746
- Official Unity 6000.6 **serialization best practices** explicitly warn that removed fields can remain as stale YAML until the asset is saved; an input-byte diff and a loaded-value diff answer different questions. It supports reporting loaded supported values distinctly from raw prefabs and never treating source equality as full runtime parity. https://docs.unity.com/en-us/engine/6000.6/manual/programming-environment/code-reload-serialization/script-serialization/best-practices

Actual buyers might need nested prefab variant/MonoBehaviour field inspection, scene overrides, import dependencies, CI and Player tests.
