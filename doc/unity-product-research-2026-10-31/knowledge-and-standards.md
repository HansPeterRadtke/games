# Unity Gameplay Systems Suite — authoritative research sourcebook

Research snapshot: 31 October 2026. Scope: owner Infra guidelines, real Raspi original-KnowMoreDiRT FileDB, downloaded official Unity books, first-party current Unity documentation, legally accessible O'Reilly preview, and the actual Unity source. This report is **not** a claim that every Infra document or all 12,372 books have been read cover-to-cover. It is an explicitly scoped, source-grounded review of material directly applicable to a Unity commercial code tool. The user has requested research **before** further development; no runtime-source modifications were performed as part of this research pass.

## Authority and repository boundaries

- Primary owner standards: Nitro `/data/infra/AGENTS.md`, `/data/infra/README.md`, `docs/guidlines/README.md`, `docs/guidlines/programming/README.md`, `docs/guidlines/configuration.md`, `docs/guidlines/testing.md`, `docs/guidlines/performance_reliability.md`, `docs/guidlines/security_privacy.md`, `docs/guidlines/source_traceability.md`, and GUI research contracts under `docs/guidlines/gui/`. Also inspected `games/standard_game_foundation.md` and `games/playability_realism_and_saving.md`. Inventory of guideline source files: 79 Markdown files, ~625 KB outside original-recordings and appendix; their metadata and primary section headings were inspected. **Full semantic reading of every guideline and every original audio recording was not established**. This limitation is documented rather than silently claimed.
- For programming, the owner's rules require input/process/output tracing, meaningful semantic naming, bounded responsibilities, modular interfaces, changeability, externalizable changing policy, avoiding invented abstractions, explicit errors, source-controlled reproducibility, and multi-pass failure-path/code-review auditing. A passing compile/test alone cannot demonstrate code quality.
- For configuration, distinguish mechanism invariants from likely-to-change behavior. Every behavior-tuning parameter must have a descriptive name, documented unit and range/default, consequences of change, applicable modes, validation, and one effective source of truth. Support designers in the Unity Inspector without requiring editing source. Avoid an exposed parameter explosion; configurable **policy** is the goal.
- For GUI, every screen must answer a user question; controls must show immediate honest feedback and failure states; make dangerous or destructive operations explicit; verify resized/low-resolution UI and keyboard/accessibility; keep advanced diagnostics discoverable without overwhelming the primary workflow. Actual Unity Editor window/Inspector behavior requires live testing.
- All original knowledge reference PDFs and downloaded assets must remain on Raspi outside Git. Do not bundle publisher copyrighted e-books in a commercial Unity package. The new Unity books were downloaded through the owner’s original curated knowledge-library source whitelist and standard downloader; the separate Unity source worktree remains untouched by this acquisition.

## Raspi FileDB, source integrity and retrieval

Verified Raspi hostname `raspi`. The curated library originally held 12,365 files / ~66.5 GiB. Seven genuinely available first-party Unity Technologies PDFs were added through the **original** Infra whitelist and original downloader. The latest downloader reported **12,372 of 12,372 curated sources present**, no missing or failed items, ~66.6 GiB. Their full original SHA-256s are held in the downloader ledger. These are privately downloadable publisher reference copies, not redistribution assets.

Queried real native KnowMoreDiRT via `knowledge-library-filesystem find`, `status --verify`, `search-semantic`, and `knowledge-library-semantic status`. Before source addition, 12,357 original sources had 43,658 real KMD vectors. Semantic ranking was materially noisy for exact Unity gameplay questions: irrelevant business and skills files ranked highly, so title/path filtering and direct original PDF page reading were mandatory. **Do not treat similarity scores as evidence of source authority.**

After adding seven publisher originals, the downloader ledger and content catalog reported all 12,372, but native FileDB `status --verify` still reported only the former 12,365 paths, missing the newly downloaded seven. **This is a genuine incremental metadata coverage defect, not missing PDFs.** The wrapper’s `refresh` explicitly refuses to replace an existing DB containing semantic chunks; triggering it would not solve this and could jeopardize vectors. Do not run a destructive rescan; the KMD owner needs a version-compatible append/migration for these seven original `filesystem_entries` and then verified semantic extraction/embedding. The original FileDB and existing 43,658 vectors were left intact.

## Newly acquired first-party complete technical references and actual reading

Each path is relative to Raspi `/data/var/Knowledge Library/`. Page numbers below identify original *PDF pages* from the corresponding first-party file, not generated chunk sequence numbers. PDF content was extracted from the actual original with Poppler and selectively read; original diagrams remain available in the same PDF.

**1. `unity-engine/unity6-csharp-clean-scalable-style-guide-2025.pdf` — Unity 6 C# style guide (2025, 65 PDF pages).**
Original publisher page: https://unity.com/vn/resources/c-sharp-style-guide-unity-6 . Read original pp. 11–21 and 23–26, examined table of contents and further topics. Conventions: meaningful, pronounceable type/method/parameter names and question-shaped Boolean APIs; PascalCase for public types/members and camelCase for locals; events named for before/after meaning; namespaces prevent collisions with other Asset Store code; prefer `[SerializeField]` on private fields rather than writable public API, use ranges and coherent serializable Inspector groups; consistent brace and style rules matter more than arbitrary style choice. **Project consequence:** existing generic `HPR` namespace across all ten modules, large integrated controller, unexplained defaults and ad-hoc editor form do not meet the stated changeability goal; publish an explicit style/configuration/API guide, not just more comments.

**2. `unity-engine/unity6-design-patterns-solid-updated-2024.pdf` — Level up your code with design patterns and SOLID, actual Unity 6 preview edition (created July 2024, 148 PDF pages).**
Original publisher page: https://unity.com/resources/design-patterns-solid-ebook . Verified exact file cover, TOC, and read selected pp. 8, 10, 13, 23, 31, 33, 36, 45, 75, 77, 85, 88, 93, 95, 100, 107, 112, 114, 115, 124, 130, 136, 141. The book concretely addresses single responsibility, interface segregation, dependency inversion, Command, Observer, State, MVP/MVVM, Strategy and Unity UI Toolkit data binding. It includes an actual example `SceneBootstrapper` with an **opt-out** to avoid taking over the Editor unexpectedly. The StateMachine, event and UI examples emphasize reusable small contracts and separating model, view and interaction policies. **Project consequence:** the HPR demo’s single large controller owns input, enemy, firing, world registry, saving, inventory, HUD, and lifecycle, contradicting the publisher’s example of focused units; separate demo driver/presenter/configuration into independently testable responsibilities **after** contract and market scope are settled.

**3. `unity-engine/unity6-scriptableobject-architecture-2025.pdf` — Create modular game architecture with ScriptableObjects, Unity 6 edition (2025, 75 PDF pages).**
Publisher: https://unity.com/resources/create-modular-game-architecture-scriptableobjects-unity-6 . Read selected pp. 8, 10, 12, 20, 22, 27, 33, 38, 43, 49, 58, 64, 70. Original p.20 explicitly distinguishes shared designer-facing config assets from **persistent runtime state**, which requires separate durable storage; changing an asset in the Editor can persist changes and contaminate later tests. Other relevant sections address Inspector-facing data containers, ScriptableObject-based event channels, extendable data IDs, composable enemy behaviors, designer editability and separation of assets from executable mechanisms. **Project consequence:** the HPR source’s ScriptableObject item/ability/enemy/weapon definitions are a useful foundation, but a safe commercial product must not treat mutable definition assets as per-run state; expose validated authoring data and ensure example scene rebuilding does not overwrite buyer edits.

**4. `unity-engine/unity6-ui-toolkit-advanced-developers-2025.pdf` — UI Toolkit for advanced Unity developers, 2025, 148 PDF pages.**
Publisher: https://unity.com/resources/scalable-performant-ui-uitoolkit-unity-6 . Inspected complete TOC, read selected pp. 29, 31, 43, 45, 59, 72, 75, 79, 82, 84, 92, 96, 97, 122, 124, 133, 143. Covers UXML for structure, USS for reusable styles and responsive layout, semantic namespacing of selectors, runtime data binding (including `[CreateProperty]`, change tracking, source path and binding mode), ListView, custom VisualElements and performance considerations. The guide separates data/model from UI and explains why direct UI polling and binding boilerplate are difficult to maintain. **Project consequence:** replace the fixed-width/height IMGUI showcase with a genuine focused first-run experience and appropriate UI Toolkit authoring window, but do not force UI Toolkit on runtime-only consumers of the core modules. For any writable Editor form, use SerializedObject/SerializedProperty/Undo, multi-object and prefab safeguards, validation and actionable messages.

**5. `unity-engine/unity6-organization-version-control-2024.pdf` — Best practices for project organization and version control, 2024, 96 PDF pages.**
Publisher: https://unity.com/resources/best-practices-version-control-unity-6 . Extracted full publisher PDF and read original TOC/early sections on project structure, source control, code standards and Unity assets. **Project consequence:** avoid duplicate assemblies and conflicting `.meta` GUIDs; prefer one clearly documented buyer root; preserve scene/custom asset modifications on updates; track original package and imported results with separate provenance and no generated assets in Git.

**6. `unity-engine/unity6-editor-productivity-2025.pdf` — Tips to increase productivity with Unity 6, 2025, 112 PDF pages.**
Publisher: https://unity.com/vn/resources/tips-improve-productivity-workflow-unity-6 . Inspected full TOC; relevant original chapters include Editor workflow and custom gizmos (pp. 8–22), Inspector/debug preview, prefab variants, UI Toolkit, asset/import automation. **Project consequence:** buyer workflows should integrate with native Inspector, shortcuts, menu and scene navigation rather than inventing a separate application that hides the actual Unity assets. Direct open-demo, selected config, scene validation and interactive mini-examples should be reversible and noninvasive.

**7. `unity-engine/unity6-game-programming-patterns-solid-2024.pdf` — older original Unity 2021 LTS edition (PDF creation 2022, 99 PDF pages).**
This PDF was initially **mistakenly labeled as the 2024 Unity 6 edition** because its landing page offered an older downloadable PDF. Inspecting its cover exposed the edition mismatch. Original was preserved unchanged and the Infra source catalogue was corrected to state the genuine 2021 LTS edition. The distinct actual Unity 6 July-2024 edition was then acquired as item 2. **Never silently treat edition mismatch as a current Unity API reference.**

Unity’s original source e-books remain copyrighted. Their **ideas** inform architecture and tests, but do not copy substantial excerpts, book images, or publisher source into our for-sale package.

## The Art of Readable Code — exact availability

Dustin Boswell and Trevor Foucher, O’Reilly Media, 2011, 206 pages. Publisher page: https://www.oreilly.com/library/view/the-art-of/9781449318482/ . Its publisher-hosted overview and Chapter One preview are accessible for direct reading, but the **complete book requires authorized access**. The original complete book has **not** been downloaded and must not be sourced from unauthorized mirrors. From the official publisher contents and legal preview, directly applicable themes are: minimize *time to understanding*, semantic rather than opaque names, distinguishably bounded variables/ranges, limited nesting, one task at a time, and tests with strong names/error messages. This is also independently reflected in Unity’s legally downloaded C# style guide. Publisher preview chapters are not evidence the whole O’Reilly book was read.

## Current first-party Unity Editor/packaging/QA contracts

Verified official documentation at time of review:

- Unity Asset Store Publishing Tools / Validator, https://docs.unity.com/en-us/asset-store/publishing/asset-packages/upload — official Editor validator exists and tests submission guideline conformance. **Use the original validator** before submission; do not reinvent it or claim local import success equals compliance.
- Unity package layout and Samples, https://docs.unity.com/en-us/engine/6000.3/manual/ — official package asset layout, UPM metadata, assembly definitions, package tests. Standard Asset Store `.unitypackage` root remains supported. UPM Store publishing was still limited/early access, not an automatic replacement for the current uploader.
- Unity Test Framework EditMode vs PlayMode, https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/test-framework-introduction/getting-started/edit-mode-vs-play-mode-tests — tests need proper asmdefs and assembly references; PlayMode can exercise runtime frames and player builds, while EditMode covers authoring code. Unity also recommends independent manual playability/visual testing in addition to automated checks.
- Unity Editor data/Inspector: SerializedObject/SerializedProperty/PropertyDrawer/UI Toolkit and `SettingsProvider`. No private Editor reflection, forced registry installations or silent changes to unrelated assets. Multi-object editing, Undo/Redo and prefab override handling require explicit validation.
- Unity's October 2026 marketplace rules demand clear product value, truthful AI provenance/marketing, readable namespaced source, sufficiently differentiated submissions, valid documentation and compatibility. Starting with Unity 6.6, disabled-domain-reload Play Mode must work; a legacy `AssetDatabase.ExportPackage` API warning in actual Unity 6.6 imported HPR source is currently **an observed defect**, not a theoretical concern.

## Owner workflow and code-quality implications

The owner’s programming/configuration/GUI instructions are more demanding than many generic template tutorials: avoid unbounded hidden work, document failure and repair, test corners with adversarial and real cases, preserve unrelated user edits, instrument true state, verify the completed UI at multiple sizes, and expose only meaningful settings with semantic types, units and validation. Our programming product must make the safest path the easiest one, and the best evidence of quality will be reproducible **time-to-first-working-integration and successful customization by developers**, not the number of modules or passing tests alone.

This sourcebook is research evidence; actionable ranked product defects and market requirements are in the two companion documents in this directory. No source-code changes were made during the research stage.
