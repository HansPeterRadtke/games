# HPR Project Preflight — new combined Editor tool, November 20–21, 2026

## Product hypothesis, evidence and economics

A combined preflight lets a developer run two narrow read-only checks from one Editor window: (1) potential Unity legacy/new Input System migration mismatches, and (2) Animator transition/state/Blend Tree parameter contracts. It calls two existing original HPR auditor implementations rather than creating another broad asset-reference cleaner. It shows both statuses and allows a user-initiated, create-only combined JSON report. The main benefit hypothesis is fewer manual setup steps when adopting Unity game assets or migrating an older project; price and real sales conversion **are unverified**. This is likely more useful as an added buyer-confidence tool alongside the larger HPR Gameplay Suite than as another unsupported paid micro-product, because the owner wants credible net income per owner hour with minimal ongoing support.

Community evidence: Unity 6.7 alpha users reported legacy `Input.GetKeyDown` errors and lockup while discussing lack of source warnings, which makes an audit workflow relevant (https://discussions.unity.com/t/old-input-causes-lockup-6000-7-0a2/1731096). Other Unity developer reports show legacy/new input mismatches in official tutorial scripts (https://discussions.unity.com/t/unity-essentials-pathway-publishing-essentials-esc-key-fails-to-return-to-main-menu/1704765). Unity 6.7 and 7.0 now ship Input System as an Editor-versioned core package (https://docs.unity.com/en-us/engine/6000.7/manual/packages-list/packages-all/pack-core/com-unity-inputsystem), so active-package detection needs future native testing on those Editors. Animator reference/parameter failures also occur after refactors, but the team must distinguish them from clip-path binding repairs and from current fixed Unity Editor bugs.

Competition: paid Animation Tools includes missing clip-path reference repair, audio timeline and animator behavior utilities (https://assetstore.unity.com/packages/tools/animation/animation-tools-324462). General validators, including free Assets Validator and comprehensive Odin Validator, already scan a broad range of missing scripts and references (https://assetstore.unity.com/packages/tools/utilities/assets-validator-283795 ; https://assetstore.unity.com/packages/tools/utilities/odin-validator-227861). Project Validator offers rules, JSON/CSV reporting and UI navigation (https://assetstore.unity.com/packages/tools/utilities/project-validator-410282). This bundle must **not** be marketed as comprehensive project validation, automatic repair, independent technical superiority, AI-generated paid exclusivity or a proven commercially demanded product. No independent purchasers or support economics were observed.

## Actual original implementation

`unity/tools/release/preflight_bundle/Assets/HPRProjectPreflight/Editor/HprProjectPreflightWindow.cs` is an original Editor-only UI that calls the existing `HPR.InputReadiness.HprInputReadinessAudit.Analyze` and `HPR.AnimatorContract.HprAnimatorContractAudit.ScanProject` for the same active project. It combines statuses conservatively: if either report is incomplete, the combined result is **INCOMPLETE**; definite risks from either are **ISSUES_FOUND**; uncertain input code is **REVIEW_REQUIRED**; otherwise only scoped checks are reported as clear. User-initiated export uses `FileMode.CreateNew` and never overwrites an existing file. The package includes both existing product folders and a third new `HPRProjectPreflight` vendor folder, and excludes all private QA/export scripts. It does not modify project assets, send network data, modify settings, convert Input code, repair Animator Controllers or guarantee actual Player behavior.
