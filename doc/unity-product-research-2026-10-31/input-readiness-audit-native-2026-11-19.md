# New HPR Input Compatibility Audit — actual package, source safety and Unity QA

**Date:** November 19, 2026. **Status:** working, unpublished Editor-only candidate; NOT buyer-release approval. This is a separate product from the HPR Gameplay Systems Suite and never alters or replaces that archived release.

## Product and rationale

The `HPR Input Compatibility Audit` is a simple read-only EditorWindow for Unity projects changing between legacy Input Manager and new Input System. It reports the actual project setting (`Legacy only`, `New only`, `Both`, `Unknown`), the detected Input System package version, and source-file lines containing *potentially incompatible input API calls*. It detects missing/unknown settings, new-only configuration with no installed Input System package, unguarded legacy APIs in new-only projects, and unguarded new APIs in legacy-only projects. It honors simple `#if ENABLE_*` and `UNITY_EDITOR` guards and marks unknown compiler symbols as uncertain. Findings include source path and line; no code is edited, rewritten, imported or deleted. It offers an explicitly user-chosen, create-only JSON export. It is a heuristic rather than a compiler/static dependency graph; composite preprocessor expressions, runtime reflection/aliasing, uGUI `StandaloneInputModule`, embedded UPM package code and genuine Input device behavior need separate verification. A missing scan result is not a pass.

This narrow product is based on reproducible 2026 Unity developer discussions about mixed Input backends, not on invented buyer counts or sales. The public research, competitors and economic limits are in [Editor tool demand, November 19](editor-product-demand-2026-11-19.md). General asset cleaners and reference search are particularly crowded, and larger Input System converters already exist. Its price and willingness-to-pay remain unvalidated; do not claim differentiated commercial value solely from this prototype.

## Important active Build Profile correction (latest source, November 19)

After source review, the official Unity Issue Tracker and Build Profile manual revealed a real false-negative risk: an active custom Build Profile can override global input handling in Play mode and builds. A build that checked only global `ProjectSettings.asset` could incorrectly report `Both` while the active profile runs `New only`. The initial solution attempted to access `BuildProfilePlayerSettings` from newer documentation; native Unity `6000.6.8f1` **rejected that type at compile time**, so the failed attempt and log were retained in `qa-v4.unity.log`. The corrected source uses the public `BuildProfile.GetActiveBuildProfile()` API and **fails closed whenever any custom profile is active**, reporting `ACTIVE_BUILD_PROFILE_OVERRIDE` and `Unknown` with instructions to inspect the profile and perform a real Player build. It does not silently rely on global settings or invoke unsupported reflection. The installed Editor compiled this correction and the nine private QA checks passed (`qa-v4-retry.unity.log`, `private-test-fixtures-v4-retry/qa-receipt.txt`). A custom-profile-with-override runtime regression remains **unverified** in native Unity; do not call this feature independently accepted yet.

The packaged product remains strictly Editor-only, read-only, separate from the gameplay suite and unpublished.
