# HPR Animator Contract Audit — new product research and private production (November 20, 2026)

## Real problem and competitor baseline

Unity Animator transitions depend on named controller parameters, and removing/renaming parameters can leave stale transition conditions. Official Unity manual: https://docs.unity.com/en-us/engine/6000.6/manual/animation-section/animation-mecanim/animation-animator-controller/animation-state-machines/class-transition . The Unity Issue Tracker documents missing or stale Animator parameter references including a case of renamed parameter undo (fixed in some 6.1/6.2 editions): https://issuetracker.unity.com/issues/6060/undoing-animator-parameter-name-change-breaks-references-to-it ; https://issuetracker-mig.prd.it.unity3d.com/issues/animator-conditions-tab-breaks-when-the-only-parameter-is-deleted-and-another-one-is-created . This supports a real class of developer errors, **not** a revenue estimate or evidence that the fixed bug persists in 6.6.

A broader **Animation Tools** package has missing binding repair and automation, listed near USD 24.99 with only twenty-six observed favorites, while **AnimBinder** already supports binding-path repair and automatic migration: https://assetstore.unity.com/packages/tools/animation/animation-tools-324462 ; https://assetstore.unity.com/packages/tools/animation/animbinder-368186 . A read-only parameter contract check could be a low-support utility for teams working with many controllers. Distinguish missing transition parameter contracts from hierarchy animation-clip bindings. The candidate's true willingness-to-pay, price, buyer count and support burden are all **unverified**. Most credible first commercial direction is bundling with a stronger HPR gameplay package or delivering it as an adoption/free utility pending owner/seller approval. Do not claim superior functionality or sales based on this prototype.

Generic missing-script reference cleaners, project validators, asmdef analyzers and UPM package validators are already widely available, often for free. Examples include Unity's own free UPM Publishing Tools and Project Validator, Assembly Architect, and free Missing Scripts Tool. Those broad duplicates were deprioritized for this turn. https://assetstore.unity.com/packages/tools/utilities/project-validator-410282 ; https://marketplace.unity.com/packages/tools/asset-store-upm-publishing-tools-5368745 ; https://assetstore-fallback.unity.com/packages/tools/utilities/assembly-architect-353250 ; https://assetstore-fallback.unity.com/packages/tools/visual-scripting/missing-scripts-tool-302062

## Product boundary

The standalone original `HPR Animator Contract Audit` lives in `unity/tools/release/animator_contract_audit/`. Only `Assets/HPRAnimatorContract/` is a customer asset. `qa/` is private and never shipped. It scans editable Animator Controller assets under `Assets`, including nested state machines, condition references and state-level active parameter bindings, reports missing parameter names, duplicate definitions and incompatible transition types. It offers manual object navigation but no changes, auto-fixes, code generation or account work. It is not a full animator runtime simulation, graph validator, or evaluation of custom controllers, imported model animator controllers or script-driven parameter calls.

## Commercial decision and ongoing support risk

Read-only niche checks are easier to implement and support than automatic destructive asset repairs, but *lightweight* also means a limited market ceiling. Relative priority by potential owner return, not invented sales data: **one**, finish buyer acceptance for the larger existing HPR Gameplay Systems Suite with genuine visual proof and usable demos (highest plausible unit value, highest support/release risk); **two**, bundle a separately verified Animator Contract Audit and Input Compatibility Auditor as compatible low-support add-ons to strengthen a buyer package, subject to licensing and buyer interest; **three**, sell either tiny inspector as an independent low-price tool only after testing buyer acquisition and willingness to pay; **four**, do not start generic missing-script, assembly dependency, UPM publishing-validator or asset-cleaner clones given mature free or established competition. Competing Animator repair tools and Unity's official fixes mean a claim that a standalone parameter checker is differentiated would be premature.

Estimated time to first **technical candidate** is short because a new Editor-only script and private QA reuse existing installed Unity workflows, but time to **cash** is not estimated: screenshots, store account/terms, buyer evaluation, price testing and sales approvals still have unknown lead times. The source project is publicly readable on GitHub, so the seller must not imply the code is exclusive. Any intended paid licensing, support terms, commercial promise or repo visibility change requires owner approval. This research is a production priority proposal only, not an instruction for the shared sales worker to publish.

An initial test then **passed in real Unity** using a deliberately broken Animator Controller and a correct one, with no existing project file mutation. The deliberately broken controller had stale transition conditions, wrong parameter type, stale active speed, Any State and nested state bindings. The native Editor logged the intended findings while the good controller returned no findings. Evidence: private `native-qa-one.unity.log`, `nested-native.unity.log` and adjacent receipts.

## Current cross-version and release-quality acceptance (November 20, later)

The source review found that active Animator state bindings were checking parameter *existence* but not type. A real defect was reproduced: a state Mirror parameter could point to a Float, and normalized Time could point to a Bool, without the audit flagging the mismatch. The scanner now requires Float for active Speed, Time and Cycle Offset and Bool for active Mirror. Native regression fixtures deliberately include both mismatches while configuring the valid controller with correctly typed state bindings. Under installed patched Unity `6000.6.8f1`, all **fourteen** native checks passed, including these two new tests, existing nested-state and Blend Tree cases, valid-controller no-false-positive check, and create-only JSON export. Evidence is `typed-state-native.unity.log` and `typed-state-native-qa/receipt.txt` in the private November 20 QA root.
