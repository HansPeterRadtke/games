# Customer-owned Unity sample copy: non-destructive failure recovery

November 2, 2026, Nitro. Commercial verdict **NO-GO**. This source correction is private QA, not a newly validated Unity Asset Store release.

The existing HPR sample-copy Editor command already validates destination names, existing files and Unity metadata collisions, and creates independent customer-owned ability assets. The prior seven-change candidate saved only newly authored asset copies, avoiding Unity's global SaveAssets call.

A further source audit found a remaining race: if a copy succeeded and a later dependency-rewiring, GUID, disk-save or verification step failed, the exception handler deleted every newly-created **path**, without verifying that Unity's importer or another developer had not replaced the asset at that path in the meantime. That rollback could delete an unrelated customer-owned replacement. This is a concrete dangerous source pattern, not a runtime race already demonstrated in a customer project.

The independently owned proposal changes only the integration guide's failure handler and the already-changing buyer documentation. It retains any partial new assets, includes their Unity asset paths in an explicit error, and tells the buyer to review files and GUIDs before manually removing or retrying. It never automatically deletes or retries uncertain effects. This deliberately trades automatic rollback for stronger protection of customer data: an interrupted copy may leave incomplete new assets.

The patch is in patches/hpr-copy-failure-preserve-new-assets-2026-11-02.patch. A test-first run failed before the proposed source file was created. Five source-level regressions then passed, checking no automatic AssetDatabase.DeleteAsset call, existing collision/GUID checks, targeted SaveAssetIfDirty, actionable UI reporting and a single-file patch.

An independent offline C-sharp compiler used the installed Unity six point six and six point four managed API references, the proposed Editor guide and the existing HPR runtime/integration sources. Both compilations completed with **zero errors** and fifteen private Unity-serialized-field warnings. The earlier standalone six point six compilation had incorrectly emitted an additional obsolete-export warning because its test project omitted the Unity-version compiler symbol. Recompiling with the correct UNITY_6000_6_OR_NEWER definition selected the already-present modern UnityEditor.AssetPackage.Package.Export API, eliminating that obsolete warning. Unity's current official API reference confirms the legacy export overload is deprecated in six point six: https://docs.unity.com/en-us/engine/6000.6/script-reference/unityeditor/assetdatabase/exportpackage and https://docs.unity.com/en-us/engine/6000.6/script-reference/unityeditor/assetpackage/package/export.

A separate Mono.Cecil review of the **actual offline compiled method** found one direct AssetDatabase.DeleteAsset invocation in the earlier compiled guide and **zero** in the corrected compiled guide. The corrected method still directly invokes CopyAsset and SaveAssetIfDirty, and contains the specific partial-copy and manual-review error messages. This proves the direct deletion call is absent from the compiled proposed C-sharp method; it does not prove that the entire Unity Editor import/copy process is non-destructive under every possible race.

A separate private package was rebuilt from the original frozen 161-asset archive, substituting only the seven already-permitted source/documentation payload paths. It preserves all **161 Unity GUID identities** and **ten assembly definitions**; the independent archive-policy and GUID-upgrade checkers passed. Two independent builds of that private package yielded byte-for-byte identical archives. The original frozen binary, original commercial worktree and other agents' dirty QA files remained unchanged.

The complete independent Python regression matrix passed **172 tests**. The new source remains in an isolated QA worktree. Full Unity Editor compilation, a forced mid-copy error test, populated-customer save/reopen, URP plus new-only Input System, no-domain-reload Play mode, final visual UX and competitor buyer trials remain **unverified**. The existing broker-controlled URP worker remained active but CPU-constrained, and no additional long-running Unity job was launched.
