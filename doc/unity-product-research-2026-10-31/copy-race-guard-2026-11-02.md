# Customer-owned Unity ability copying: late collisions and failed CopyAsset

November 2, 2026. PRIVATE ENGINEERING QA. Commercial status: NO-GO.

The original HPR Editor sample copier preflighted destination files before copying dependencies. Another importer could create a destination after that one-time preflight. Also, Unity's AssetDatabase.CopyAsset documentation explicitly states that a false return means part of the copying process may have failed. The old error tracked only already-confirmed copies, not the last attempted file. The relevant first-party reference is https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/assetdatabase/copyasset .

The new QA-only C# source is HprSuiteIntegrationGuideRaceGuard.cs in unity/tools/release/gameplay_suite/qa, with a reviewable patch under doc/unity-product-research-2026-10-31/patches. It immediately checks for Unity registry entries, physical asset files, directories and metadata collisions again before EACH CopyAsset call. It separately tracks the last attempted destination and clearly marks it as possibly existing if CopyAsset fails, while retaining the list of confirmed created outputs. It includes the underlying failure reason in the buyer-facing error, including any occupied destination path. The Editor now catches UnityException as well as the previously recognized exceptions. No automatic deletion or retry was added.

This is not a cross-process atomic lock. A different importer can still create an output between the last guard and the actual Unity call. A genuine Unity Editor concurrent-importer test and the VCS callback compatibility check remain required.
