# Your Mom — Model-Generated Game

The live browser game is served by the unchanged Nitro LLM Game button at `https://nitro.jonnyontherun.org/llm_game/`.

This is a Godot 4.6.1 open side-scroller with real 2D gravity, jumping, static terrain, slopes, platforms, dynamic rigid crates, collision interactions, slash and parry actions, equipment, inventory, health, stamina, mana, score, and an indefinitely extending road to the right.

The current generated player is Eryndor Thorne, a level-one warrior with 120 HP, 90 stamina, 10 mana, 14 strength, 9 dexterity, 12 base defense, one steel longsword, steel-gray chainmail, an empty off hand, slash, parry, and jump. His visible player animation uses eight reviewed transparent frames.

The initial road contains four generated and reviewed medieval RPG items. Warrior's Blade is a plain one-handed steel longsword. Medium Chainmail Chest Armor is a steel-gray medium chest item. Common Oak Treasure Chest opens on touch and grants mixed beginner loot and score. Red Health Potion restores 25 HP or enters inventory when health is full. Each item uses six identity-preserving transparent animation frames.

Desktop controls are A/D or left/right to walk, Space/W/Up to jump, F or left click in the stage to slash, Q or right click to parry, H to drink a stored health potion, and R to reset. Touch browsers use the old LLM Game browser-control model: an exact 118 by 118 pixel DOM joystick with a 48 pixel returning thumb, Pointer Events, pointer capture, normalized axes, and zero-on-release behavior. Attack, Jump, Parry, Potion, and Reset are separate DOM buttons so movement and actions can be used simultaneously. The forge is a real HTML select, input, and submit button, so Android uses its normal soft keyboard and text editing.

Web controls and information are not Godot controls painted into the rendered game. The Web export uses a custom HTML shell with three sibling regions: player HUD, game stage, and forge. The Godot canvas exists exactly once inside the stage and contains only the game render. The Web build hides Godot's native CanvasLayer; JavaScriptBridge callbacks carry normalized movement, actions, and forge requests into Godot, while Godot publishes live stats, equipment, event text, forge state, and generated-content details back to the DOM shell.

Landscape uses a browser CSS grid with HUD on the left, the game-only canvas in the center, and the forge on the right. Portrait changes the same page to HUD on top, stage in the middle, and forge at the bottom. Safe-area insets, `viewport-fit=cover`, a stage `ResizeObserver`, visual viewport resize handling, and orientation-change handling keep the canvas restricted to the stage. The stage disables browser panning and long-press behavior, while the HUD and forge remain normal scrollable and selectable browser UI.

The final public cache marker is `godot-dom-shell-rpg-v7`. A live 500 by 895 portrait test measured a 161.1 pixel HUD, a 528.9 pixel stage, and a 205 pixel forge with no gaps, overlap, or canvas children. The exact 118 pixel joystick and the action pad remained inside the stage. A trusted joystick drag moved Eryndor from 36 m to 109 m. Attack produced the live event “Eryndor Thorne uses slash for 12 weapon damage,” and Parry produced the corresponding stance event. The same running page rotated without reload to 980 by 435 landscape, measuring 196 pixels for the HUD, 568.4 pixels for the stage, and 215.6 pixels for the forge. The forge input focused as a real HTML field outside the canvas with `enterkeyhint=send`.


The LLM controls semantic content inside five fixed closed schemas: player, weapon, armor, loot, and consumable. It generates names, descriptions, visual descriptions, and enum selections. Deterministic code compiles stats, legal equipment slots, weapon actions, armor effects, consumable effects, structural image prompts, animation descriptions, and visual review requirements. Request-specific requirements are inserted into the constrained-decoding schema before generation. Independent schema, cross-field realism, request-adherence, and Godot validation gates reject contradictory output.

Thor generates assets in two stages. SDXL first produces a canonical isolated character or item image. A local Qwen vision-language model rejects candidates with the wrong category, missing parts, malformed anatomy or geometry, duplicate equipment, ungrounded materials, clutter, or a poor extraction background. SDXL image-to-image then generates restrained identity-conditioned animation frames from the accepted source. Mid-animation frames are reviewed again. Transparent PNG, looping GIF, and Godot sprite-sheet outputs are published only after alpha, geometry, frame-count, distinct-frame, canonical-review, and identity-preservation checks pass.

Run `tests/run_all.sh` for assets, schemas, semantics, player state, equipment, actions, physics, interactions, open-world extension, the custom DOM shell, bridge movement and release, bridge jump and actions, forge validation, import, and runtime tests. Run `tests/run_integrations.sh` for local LLM, object-service, Thor, and existing grounded player status checks. Run `deploy/build-web.sh` to create the tested Web export, and use the privileged `deploy/install-nitro.sh` to deploy with Apache backup and rollback protection. Run `deploy/nitro-verify.sh` to verify the local and public routes.

The default Nitro `godot` command is the Mono editor. Browser export uses the separately installed official standard Godot 4.6.1 editor because Godot 4 Mono does not export to Web.
