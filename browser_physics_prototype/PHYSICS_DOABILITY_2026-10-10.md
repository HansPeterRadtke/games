# Game physics feasibility — 2026-10-10 (Nitro)

This is measured engineering evidence for the game recordings, not a claim of biologically realistic locomotion.

- Engine: `@dimforge/rapier3d-compat` version `0.17.3` with 3D rigid bodies at a fixed 60 Hz, Canvas 2D presentation only. The simulation has three-dimensional transforms; the demo constrains the player's travel to one horizontal lane.
- The original passive ragdoll contained six spherical-jointed bodies. The new module has ten individually simulated 3D rigid-body segments and nine hinge joints with tunable position/velocity motors. The head, left/right arms, elbows, thighs, shins, hips, and knees are represented separately.
- Important *tested* API behavior: motorized 3D revolute joints produced almost no rotation when both connected bodies were individually locked to the XY plane. Keeping only the root constrained and letting each limb follow revolute-joint constraints restored motion; this was demonstrated by the isolated `tests/motor-doability.mjs`, `tests/active-study.mjs`, `tests/motor-strength-study.mjs` and `tests/active-regression.mjs` studies. Do not assume all 3D joints work if every linked body is separately constrained.
- A completely passive rig collapses under gravity. The *assisted* rig uses joint motors plus a force/torque-based root pose-tracker, not direct teleportation. The tracker represents external animation assistance, **not** biomechanically credible balance or real muscle forces. Purely contact-based foot support was not stable in the initial feasibility sweeps. Do not promote this experiment to a biological active-ragdoll implementation without measured balance and locomotion studies.
- The pose driver can switch balance/step/passive states; collisions retain physical authority, and a local stone contacts individual shins even while the torso moves forward. `tests/local-obstacle-regression.mjs` explicitly checks per-leg Rapier contacts and continued torso movement, and emits collision-sourced semantic events.
- Separate Rapier knee hinge limits are now enforced on both knees (`[-0.2, 1.6]` radians), and the motorized gait remains stable under the limit test. The older pinned Rapier 0.17.3 JS API does not expose `setMotorMaxForce` on these joint handles (newer docs mention it); do not assume motors have calibrated maximum torque.
- A controlled healthy-vs-sprained simulation demonstrates a measured maximum 0.071 radian (~4 degree) left-knee pose difference, under otherwise identical world conditions. The sprain currently reduces that motor's stiffness. It does **not** model a torn ligament, meniscus injury, bleeding, localized tissue damage, or validated gait compensation. These are future model requirements, not implied implemented functionality.
- `tests/active-regression.mjs` checks standing target tracking, physical impulse response, recovery from passive collapse, motorized limb motion, local injury state and state persistence; `test-physics.mjs` covers fence crossing and manual controls.
- PRSE: `semantic-world.js` and `world-bridge.js` now materialize an identified off-screen semantic actor into a live 3D rigid body inside perception, capture physical changes when leaving perception, de-materialize the physical body, and recreate it consistently after return or saving/loading. This is a tested seed mechanism, **not** complete LLM-generated world construction or a full field-of-view-based spatial materializer.
- Production needs: torque-limited muscle/activation and fatigue; mass/inertia calibration; footing/contact-based balance, stepping, stumbling, getting up; anatomical joint limits; localized tissue and injury consequences; dynamic semantic-to-physical interactions under arbitrary camera and 3D movement; actual mobile performance and user playtesting. Each is a separate feasibility test before treating it as implemented.

All sample assets remain CC0 Kenney New Platformer Pack (`https://kenney.nl/assets/new-platformer-pack`); the lightweight mannequin is Canvas geometry representing physical segment transforms, not a downloaded authored skeletal character.

To verify from this directory: `node test-physics.mjs && node tests/active-regression.mjs && node tests/local-obstacle-regression.mjs && node tests/prse-transition.mjs && node tests/semantic-input-regression.mjs && node tests/performance.mjs`.

## Extended game-system vertical slice — 2026-10-10, second pass

The initial ragdoll laboratory was **not** the intended game. Its controls are now relegated to an optional, collapsed `Articulated physics laboratory` section. The default browser page is a playable exploration-and-repair slice with the same authoritative 3D core.

### Demonstrated gameplay, not mocked progression

A neutral, authored PRSE world seed gives the player a grove, loose timber, an experimental mechanism, an obstructing physical fence, a path traveler, water, a missing timber bridge, and a far bank. The player must find and carry two six-kilogram planks, physically cross the fence, repair the bridge from nearby, and move across the stream. The simulation has a **real opening in the 3D ground collision**; repair materializes a **real 3D bridge collider**. The existing crate is a genuine obstacle: `tests/gameplay-journey.mjs` required jumping over it during the physical crossing. This is deliberate emergent play, not an instantly awarded quest teleport. The default gameplay interaction key is E; the separate research action is F. Saving remains available at any moment.

`character-model.js` represents carrying mass, fatigue, hydration, hauling practice, and localized knee impairment as separate quantities. Carrying two planks reduces the provisional locomotion target from 100% to about 78%; the physics core then uses forces/impulses against the player rigid body to approach that target. **This is a feasibility model, not empirically calibrated biomechanics.** Injury effects are task- and tissue-specific placeholders, not realistic diagnoses. The old ragdoll remains a separate experimental mechanism.

`hidden-mechanism.js` implements a fixed-parameter bounded recurring signal. Observing the instrument yields measurements and trend notes, not its underlying formula. Performing the correct action at an experimentally discoverable time activates a kinematic 3D lifting fence whose collision geometry moves over approximately 1.65 seconds; the activation, gate progress, measurement journal, and physical state persist. Across 2,000 sampled time points, 207 met the experimental success threshold. That fraction is specific to this function/time window and not a universal balance recommendation. This small system implements **one** hidden rule, not the full research/frequency/ritual proposal.

`text-adapter.js` uses exactly the same GameCore and typed commands as Canvas and keyboard/touch controls. `tests/modality-contract.mjs` demonstrates matching headless text and graphical command sequences to within 1e-5 metres, and textual fence crossing through real physical movement. There is currently no freely rotating 3D camera; three-dimensional collision and transforms exist even though movement is constrained to the side-view plane.

### PRSE and generated-world doability

The world stores descriptions, source lineage, durable identities, state and physical conversion hints separately from presentation. `world-bridge.js` converts nearby entities to whitelisted Rapier 3D objects. Off-screen world advancement now runs in coarse semantic steps rather than requiring a physics body for every distant entity. On leaving perception, changed physical transforms are recorded back into semantic state. `world-generator.js` builds and validates bounded (eight-region) deterministic world extensions ahead of travel, tests stable IDs, preserves edits on reload, and refuses malformed or unbounded physics proposals. The generated path is a feasibility stub, not an autonomous LLM-driven story.

**Real local LLM feasibility check:** Nitro contacted the existing Jetson `llama.cpp` endpoint using Qwen3.8-27B and requested one constrained JSON environmental description. A single attempt succeeded (HTTP 200, 50 predicted tokens, 9.88 seconds wall time) and returned `Mossy Stone`, a rock description. That tested proposal is stored as `llm-proposal-sample.js` and placed in the first additional procedural region with source lineage; it ships as small static data, so browser gameplay stays offline-capable. This is **one successful probe**, not evidence that unrestricted generated stories, 3D scene synthesis, or latency are production-ready. The experimental response log is retained outside Git at `/data/var/llm_game/studies/llm-proposal-20261010.json`.

### Tested on the real public client

The public web route is unchanged: `/llm_game/`. On Nitro, isolated browser-context tests exercised the **visible gameplay UI** to collect two real planks, cross the physical fence using a semantic goal, and repair the bridge. The same tests completed at a simulated 320 CSS-pixel mobile viewport, checked tap targets and layout overflow, verified Enter focuses the text box, saved and reloaded the game, and verified local simulation continues with simulated network disconnection. Physical full-game completion, obstacle/bridge contacts, resource accounting, hidden timing, character load effects, save/reload, PRSE transitions, world proposals, and text/graphical parity are independently tested in headless Node/Rapier. A successful automated visual layout inspection does not substitute for a human playtesting fun and clarity.

Main remaining technical unknowns: real 3D locomotion, anatomical motors and foot-ground balance, calibrated fatigue/injuries, semantic generated story consistency across long periods and many entities, LLM output reliability/latency across broad prompts, narrative interaction, audio and accessibility beyond basic browser controls, actual weak Android-device frame rate and loading time, and player enjoyment/balance. No assertion of completion is made for these.

## PRSE narrative/physical round-trip study (October 10, follow-up)

This is a **bounded feasibility study**, not a finished autonomously written game. It follows the recordings' central idea of a semantic/literary world that becomes physically real within perception and records persistent consequences when the player leaves.

**LLM prose -> physical scene:** An existing local Qwen3.8-27B on Jetson received an authored paragraph describing an abandoned riverside shelter and returned four objects (oak bench, beeswax candle, clay jug, handwritten note) with descriptions, spatial coordinates, dimensions, masses, and support relations in JSON. Generation took **69.31 seconds**. This output did **not** pass direct physical validity: a 2-mm-thick paper was rejected by an overly broad object-size check, and three suggested center heights contradicted the explicit support surfaces. `scene-translation.js` subsequently validates identities/relations and independently corrects bench, candle and note support heights. A real Rapier test proves the candle physically rests on the generated bench (approximately 0.524m center height), not hovering through it. See `generated/llm-scene-study.json`, `tools/translate-prose.py`, and `tests/scene-translation.mjs`. The browser loads the small prevalidated object data, not the heavyweight LLM inference service.

**LLM-authored interaction candidates:** A second Qwen3.8-27B call (35.87 seconds) suggested seven object interactions. Only **three** matched the actual available type/verb combinations (light the candle, read the note, pour water). Four suggestions incorrectly tried to `extinguish` unrelated objects. They remain in `generated/llm-affordances.json` as negative evidence, but are **not executable**. Only prevalidated labels in `generated/llm-affordances.js` enter the scene; `gameplay-rules.js` independently enforces distance, object state, typed verb and physical consequences. `tests/affordance-boundary.mjs` rejects impossible object/action pairings and hostile metadata. Generated instructions never become executable JavaScript.

**Physical/semantic -> updated prose:** Two attempts to ask the same local model to rewrite the fire-damaged scene into coherent prose **timed out** after 90.49 and 50.31 seconds, respectively, despite endpoint health being available. The failed responses are retained in `generated/llm-aftermath-study.json` and `generated/llm-aftermath-compact.json`. Do not claim real-time or reliable model-based story rewriting; that direction remains an open feasibility question. For now, deterministic semantic updates and the narrative adapter produce honest, context-specific text from the current durable facts without resurrecting destroyed objects.

**Bidirectional world change in the playable demo:** The shelter is a physically materialized subset of the world, with stable IDs and literary descriptions. The player can read the warning, light a candle, physically knock it sideways, deliberately ignite the paper, pour remaining water on the fire, or leave. Ignition schedules a typed causal chain of smoldering paper, fire, ashes, scorched bench and a smoke-damaged shelter; water can interrupt the chain. In the player's presence the visible scene progresses through rendered stages (not an instant room replacement). While the player is away, these changes remain semantic and no distant flame particles or room physics need to be simulated. The old bench remains physically standing after scorching, rather than being abruptly deleted. When the player returns, soot and ash alter both visible presentation and textual description. The actor's prior knowledge of a warning survives even though the physical note can become unreadable ash; a distant traveler does not learn of a shelter fire until informed by a character who actually observed the consequences. Tests: `tests/causal-world.mjs`, `tests/npc-knowledge.mjs`, `tests/narrative-roundtrip.mjs`.

**Further generated literary branches:** Separately authored/reviewed local model samples are present in `generated/story-region-bank.json`, with reproducible branching based on the **actual stored bridge/fence state**; `llm-region-adapter.js` produces typed spatial entities for the physical world. Tests check branch selection, actual Rapier objects, validation, no retroactive changes to already materialized story, and save/reload. This remains bounded, pre-generated world branching rather than unlimited background inference.

**Simulation/output contracts:** The authoritative core retains 3D rigid bodies, typed game events with globally monotonic sequence IDs, semantic revisions/source lineage, bounded long-lived causal tasks and short physically simulated local events. The text adapter and Canvas adapter share the same core commands. Snapshot v5 retains a pending `wait` command, fire queue, semantic revisions, generated regions, object conditions, learned facts, timed machinery and all physically active bodies. Prior v4 saves are migrated without overwriting previously generated objects. After loading, partially burned and wet objects cannot revert silently. `tests/save-migration.mjs` verifies rejection of malformed saves before they mutate physical bodies.

**Known limits:** The causal model is deliberately simplified chemistry (no validated heat-transfer or fluid solver); the current sensor model uses distance rather than actual raycast visibility/occlusion; 3D objects have coordinates but the current presentation remains a simple constrained side view; the local LLM does not reliably rewrite dynamic prose on demand. The original scene text is stored with structured facts and generated descriptions rather than being an unconstrained literary-only database. The next research should target validated narrative state revision and truly generative interactions without losing deterministic physical authority, while measuring model latency, scene consistency and mobile hardware performance.

**Natural-language action feasibility:** `semantic-command.js` is a lightweight standalone deterministic object/verb matcher rather than an unrestricted LLM. Its doability test recognizes 13 distinct intended expressions and rejects 14 invalid/ambiguous/dangerous-looking commands, then verifies genuine `light`, `extinguish`, `read` actions and physical reach through `GameCore`. This implements the recording's nearest/action vocabulary idea in a bounded baseline and does not imply unrestricted language understanding. Tests: `tests/semantic-command-study.mjs`.
