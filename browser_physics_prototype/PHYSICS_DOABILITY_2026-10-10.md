# Game physics feasibility — 2026-10-10 (Nitro)

This is measured engineering evidence for the game recordings, not a claim of biologically realistic locomotion.

- Engine: `@dimforge/rapier3d-compat` version `0.17.3` with 3D rigid bodies at a fixed 60 Hz, Canvas 2D presentation only. The simulation has three-dimensional transforms; the demo constrains the player's travel to one horizontal lane.
- The original passive ragdoll contained six spherical-jointed bodies. The new module has ten individually simulated 3D rigid-body segments and nine hinge joints with tunable position/velocity motors. The head, left/right arms, elbows, thighs, shins, hips, and knees are represented separately.
- Important *tested* API behavior: motorized 3D revolute joints produced almost no rotation when both connected bodies were individually locked to the XY plane. Keeping only the root constrained and letting each limb follow revolute-joint constraints restored motion; this was demonstrated by the isolated `tests/motor-doability.mjs`, `tests/active-study.mjs`, `tests/motor-strength-study.mjs` and `tests/active-regression.mjs` studies. Do not assume all 3D joints work if every linked body is separately constrained.
- A completely passive rig collapses under gravity. The *assisted* rig uses joint motors plus a force/torque-based root pose-tracker, not direct teleportation. The tracker represents external animation assistance, **not** biomechanically credible balance or real muscle forces. Purely contact-based foot support was not stable in the initial feasibility sweeps. Do not promote this experiment to a biological active-ragdoll implementation without measured balance and locomotion studies.
- The pose driver can switch balance/step/passive states; collisions retain physical authority, and a local stone contacts individual shins even while the torso moves forward. `tests/local-obstacle-regression.mjs` explicitly checks per-leg Rapier contacts and continued torso movement, and emits collision-sourced semantic events.
- A left-knee sprain currently reduces that motor's stiffness. It does **not** model a torn ligament, meniscus injury, bleeding, localized tissue damage, or validated gait compensation. These are future model requirements, not implied implemented functionality.
- `tests/active-regression.mjs` checks standing target tracking, physical impulse response, recovery from passive collapse, motorized limb motion, local injury state and state persistence; `test-physics.mjs` covers fence crossing and manual controls.
- PRSE: `semantic-world.js` and `world-bridge.js` now materialize an identified off-screen semantic actor into a live 3D rigid body inside perception, capture physical changes when leaving perception, de-materialize the physical body, and recreate it consistently after return or saving/loading. This is a tested seed mechanism, **not** complete LLM-generated world construction or a full field-of-view-based spatial materializer.
- Production needs: torque-limited muscle/activation and fatigue; mass/inertia calibration; footing/contact-based balance, stepping, stumbling, getting up; anatomical joint limits; localized tissue and injury consequences; dynamic semantic-to-physical interactions under arbitrary camera and 3D movement; actual mobile performance and user playtesting. Each is a separate feasibility test before treating it as implemented.

All sample assets remain CC0 Kenney New Platformer Pack (`https://kenney.nl/assets/new-platformer-pack`); the lightweight mannequin is Canvas geometry representing physical segment transforms, not a downloaded authored skeletal character.

To verify from this directory: `node test-physics.mjs && node tests/active-regression.mjs && node tests/local-obstacle-regression.mjs && node tests/prse-transition.mjs && node tests/semantic-input-regression.mjs && node tests/performance.mjs`.
