# PRSE doability: what the local LLM actually knows, October 10, 2026

This is a controlled, **offline research study**, not a log of the user's Android play session. The deployed browser game does not send movement, interactions, semantic state, or GameCore events to a server and does not issue LLM requests during play. Client events exist only inside the running browser; saves use that browser's `localStorage`. The Apache web server delivers static assets and cannot reconstruct the person's gameplay from HTTP access logs. There is no server-side live game/LLM event stream to inspect.

The reproducible scenario `scene-progression-20261010.json` was synthesized by running the actual `GameCore` on Nitro. It placed a player inside the riverside shelter and used the same typed interaction commands as the GUI. The test was: materialize the shelter; light the candle; observe the candle while no paper is ignited; explicitly ignite the note; advance the world for roughly 42 seconds; inspect actual semantic/physical state and causal events.

## Observations from the real simulation core

At world time **1.17s**, a `candle_lit` event occurs. The only changed scenario state is `shelter-candle.state.lit=true`. The bench and note remain `condition=intact`; there is no ongoing fire or LLM call. The renderer draws a very small flame, only a few display pixels wide on a narrow phone, and draws the player sprite on top of the world scene. This explains why the user's action has practically no visible consequence.

At **1.83s**, a *separate explicit action* `igniteNote` calls `WorldConsequences.startPaperFire()`. It does not arise from detected candle proximity, temperature, collision, flame spread, or autonomous LLM inference. A hand-authored causal script then records note smoldering (1.83s), note burning (6.83s), bench smoldering (13.83s), note ashes (20.83s), bench burning (24.83s), bench scorched (35.83s), and shelter smoky (39.83s). The candle remains lit even after these effects. That is a state model, not physically realistic combustion.

`WorldBridge` preserves entity IDs, position, rotation, and velocities when the scene is materialized/dematerialized, but the narrative prose is not automatically updated from real physical rotation. In a separate test, applying the `tip` candle action barely displaced the candle and it settled upright; `fallen` remained false and the description stayed "standing in a metal holder". This is a real gap in the claimed bidirectional physical/semantic translation.

## Local model probes (Qwen3.8-27B, Jetson `llama.cpp`)

The model was not invoked from the browser. These calls explicitly sent **controlled test snapshots** to Jetson and recorded their results. Individual calls are not statistically meaningful reliability estimates.

**Inverse description from structured state:** `tools/test_inverse_llm.py` supplied two snapshots containing typed object condition, lit flag, geometry and support information but no original literary descriptions. The call took **43.29s** for **90 predicted tokens**. The model correctly described phase 1 as an intact shelter containing an intact note and lit candle; phase 2 as smoky shelter, scorched bench, intact lit candle, water jug and ashes. It correctly answered that the note was **not burning** in phase 1 and was **not readable** in phase 2. This is positive feasibility evidence for a narrowly scoped `structured current state -> brief text` operation, not evidence of continual story awareness or full physics reasoning.

**Numeric geometry:** `tools/test_geometry_llm.py` presented three cuboid tests asking whether a candle is supported, floating, or penetrating a bench. The call took **20.94s** for **16 predicted tokens**. Correct answers were A=supported, B=floating, C=intersecting. The model answered A=intersecting, B=floating, C=intersecting: **2/3 correct**. In case A, bench top was exactly `0.225+0.225=0.45m` and candle bottom exactly `0.525-0.075=0.45m`; the model misclassified exact contact as intersection. A deterministic geometry/physics layer is mandatory, rather than asking the LLM to decide collision truth.

**Contradictory old prose versus current state:** `tools/test_conflicting_prose_llm.py` provided obsolete prose claiming the bench and readable note were intact, plus authoritative structured state and chronological events showing ash and scorch marks. The call took **24.12s** for **88 predicted tokens**. Both booleans were correct (note unreadable, bench physically present), and the current facts dominated the obsolete prose. However, the generated text contained a nonsensical "2026-0 grey" prefix and repetitions such as "smoky air fills the heavy, smoky air fills...". Grounding and fluent prose quality must be evaluated separately.

**Earlier forward-generation evidence:** A constrained shelter-creation call took **69.31s** to produce four named objects, physical measurements and support relations. Three raw proposed center heights contradicted the model's declared support surfaces. The validation layer additionally rejected a legitimately thin (2mm) note due to an over-broad minimum-size rule; that was **a validator flaw, not evidence the LLM's note thickness was invalid**. The subsequent independent translation corrected support coordinates, and Rapier verified the candle physically rested on the bench. Model-authored affordances took 35.87s: three of seven were compatible with typed object/verb constraints; four were rejected. Two longer scene-rewrite attempts timed out after 90.49s and 50.31s. These remain negative evidence in `generated/`.

## Engineering conclusions

The LLM can interpret and narrate **supplied** current structured facts in a small scene. It does **not** presently receive or understand a user's ongoing game session. The model is unreliable at exact numeric contact relations and at producing coherent, timely rewrites from mixed stale/current prose. The engine must retain authority over physical geometry, temporal event order, object state and knowledge/visibility. Narration should use a compact, perception-filtered `state + causal event differences` snapshot and treat model text as a proposed view, with contradiction checks and cached/background execution. The most important unimplemented causal mechanic is *physical ignition when a lit, hot object actually contacts a combustible object* without a special `ignite note` command. Before claiming the PRSE round-trip is complete, test physics contact -> derived semantic state -> consistent model narrative -> persistent scene recreation, including interruptions, occlusion, and object damage.

Data: `inverse-result.json`, `geometry-result.json`, `conflicting-prose-result.json`, `scene-progression-20261010.json`. Re-run the model-based scripts explicitly; they do not run automatically in game and currently require a reachable Jetson. The latest test scripts belong in `tools/`.
