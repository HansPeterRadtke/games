## Precise error cause: types not extracted

Reanalyzed the already preserved official author label audit without changing the old parser or its negative results. Among 672 unsatisfied count requirements, 620 belonged to categories the source interpreter had never extracted, 50 were recognized but undercounted, and two were other mismatches. No amount of additional physics ticking or position optimization can create an object whose source type has never been proposed.

Across all 500 source descriptions, the frozen parser recognized 2,787 mention spans, most without an explicit number, and 300 descriptions contain repeated noun types without proven coreference. A noun expression is not automatically a new uniquely identifiable physical instance.

## Separate source-only CPU pretrained noun discovery

Built a conservative open-vocabulary candidate generator using the already installed official pretrained spaCy en_core_web_sm 3.8.0 dependency/noun-chunk model. It identifies unrecognized noun roots and noun compounds, source character offsets, explicit number words or plural lower bounds, and uncertainty about repeated references. It withholds common structural/abstract noun heads and avoids adding source-negated candidates. Candidate counts use maximum local quantitative clues rather than adding repeated mentions. Model predictions on the same 500 source descriptions were frozen to owner-private JSON BEFORE any independent SceneEval annotation labels were opened by a separate scorer.

The parser proposed 3,044 additional noun-phrase mentions and 2,898 summed per-scene distinct extra type slots. Many are ambiguous or not actual object kinds; these are UNVERIFIED source candidates, not a working ontology. The CPU model is pretrained grammar, NOT a general LLM, coreference solver, visual model or physical asset generator.

On the same previous physically accepted 197 source scenes, the *text-only hypothetical* augmentation could raise author count requirements represented from 565 to 989 of 1,237, but it also proposed 922 extra positive type slots, of which 491 were absent from the published author count labels. Absence from annotations is not automatically hallucination, but source meaning is not proven by a plausible noun phrase.

## Actual GameCore/Rapier physical comparison: generic boxes

To isolate entity COUNT from asset suitability, built a separate bounded actual native 3D materializer. It accepted only source-span-linked candidate nouns, retained every original physical ID and source literary description, refused source-negated candidates and used collision-free bounded room placement and actual native GameCore/Rapier physics/save/reentry. Crucially, all newly added candidate types received a clearly marked small PROVISIONAL 0.24 x 0.28 x 0.24 metre box with unknown material and no verified artist asset, physical scale, geometry, motion affordance, support relation or credible source meaning.

All 197 original physically valid source scenes remained geometrically valid and native-saved successfully, with no extra rejection. It added 1,110 real native Rapier rigid bodies representing 889 per-scene new type instances to 166 scenes.

Only AFTER those native worlds were saved did a second independent scorer open the SceneEval author count annotations. The current actual 3D body populations then satisfied:

| Previous baseline and experimental actual native geometry | Human 98 scenes | Assisted 99 scenes | Total |
| --- | ---: | ---: | ---: |
| Original physically satisfied author count requirements | 310/508 | 255/729 | 565/1,237 |
| Extra generic real Rapier bodies | 437/508 | 535/729 | 972/1,237 |
| Newly corrected author source count requirements | 127 | 280 | 407 |
| Previously correct clauses broken | 0 | 0 | 0 |

Of the additional 889 per-scene type instances, 467 were not in the author count annotations. The remaining 265 count requirements still fail. Generic collision boxes are real simulation bodies, but do NOT make a believable kitchen, cabinet, lamp, tool or complete scene. No source spatial relationship or visual attribute was independently validated for the new bodies.

Four thousand paired SOURCE-SCENE-level bootstrap resamples gave human observed count agreement from 61.0 to 86.0 percent, conditional improvement +25.0 percentage points, 95% conditional interval about 20.4 to 29.5. The assisted source sample increased from 35.0 to 73.4 percent, improvement +38.4 points, interval about 34.3 to 42.3. This is a previously examined benchmark, not a new pristine heldout distribution. Correlated annotation claims were NOT counted as independent cases. These conditional gains say nothing about realistic shape, source reference identity, artwork or prose quality.

## Actual GameCore/Rapier physical comparison: strict existing dimension catalog

A second NEW physically materialized arm instead accepted a proposed candidate only if the EXISTING PRSE compiler could produce its own recognized size, shape and body class. Types without existing physical geometry were refused, with no fallback box. This keeps a more credible physical category boundary, though even recognized dimensions remain provisional and not verified visual 3D assets.

On the SAME 197 original valid source scenes, the strict path had 197 native-accepted/saved scenes, no additional geometric or runtime failures. It added only **17 actual sized-category Rapier bodies** over 13 per-scene category instances and refused 916 additional candidate type placements for lacking known category geometry. Its independently evaluated author count agreement rose only from 565 to **571 of 1,237**, six extra source count requirements (three human, three assisted), no previous correct requirements lost.

This is the strongest NEGATIVE result: Open-vocabulary language recognition recovers missing candidate labels, but the physical ontology/asset pipeline cannot give nearly any of them a plausible three-dimensional embodiment. The generic box arm recovers 407 count requirements but cannot be called faithful scene generation; the strict category-size arm adds only six author count matches but avoids mass unsupported geometry.

## Why this matters for original PRSE research

This isolates separate necessary components whose outputs must never be conflated:

1. A language/discourse model must recognize source nouns, instance identities, scoped numbers, repeat references, negation, conditional clauses and ambiguity. It must sometimes ABSTAIN instead of creating a new entity per phrase.
2. A physical asset/catalog or validated generative component must supply category-appropriate metric scale, collision shape, support surfaces, containment/affordances, dynamics and appearance before tentative sources can become physically credible things.
3. A geometric constraint optimizer and the ONE existing GameCore/Rapier physics authority must check spatial positions, contacts and real events rather than allowing a model to dictate outcomes.
4. Offscreen native/semantic saves must preserve identity, causal history and contact solver state when interactions matter. The observer ledger must separately decide what a player could actually witness.
5. Generated current literary text remains a PROPOSAL subject to source and 3D fact entailment, observer causal privacy and future rematerialization tests. Merely giving a provisional box a noun-derived name is not preserving literary meaning.

Independent scientific context confirms these boundaries. SceneEval (Tam et al., WACV 2026) evaluates source counts, attributes, relations and physical plausibility separately:
https://openaccess.thecvf.com/content/WACV2026/html/Tam_SceneEval_Evaluating_Semantic_Coherence_in_Text-Conditioned_3D_Indoor_Scene_Synthesis_WACV_2026_paper.html

Holodeck (Yang et al., CVPR 2024) separates language-driven quantities/sizes and spatial constraints, asset retrieval from Objaverse and layout optimization:
https://openaccess.thecvf.com/content/CVPR2024/html/Yang_Holodeck_Language_Guided_Generation_of_3D_Embodied_AI_Environments_CVPR_2024_paper.html

OpenScene (Peng et al., CVPR 2023) uses open-vocabulary object grounding in EXISTING observed 3D scenes, a relevant but reverse-direction problem:
https://openaccess.thecvf.com/content/CVPR2023/html/Peng_OpenScene_3D_Scene_Understanding_With_Open_Vocabularies_CVPR_2023_paper.html

None was reproduced here. The PRSE experiments use a CPU pretrained syntactic noun extractor, not their full language, perception, asset retrieval or layout pipelines.

## Limitations, artifacts and next genuine experiment

This is exploratory research on already examined SceneEval source data, with some previously reviewed gold labels. The noun rules were general and frozen before NEW independent scoring, but claims of unbiased prospective generalization would be false. Published type-count annotations may not list every legitimate source noun; 467 unannotated new instances are a warning, not a calibrated hallucination probability. Category syntax errors also produce some obviously questionable candidates. Per-object source identity/coreference, all spatial relations, physical scale, real assets, visual attributes, offscreen unscripted actor activity and fluid expressive literary rewriting remain untested or unsupported in these new arms.

The next scientific comparison should use genuinely new unseen literary source paragraphs and an instance-aware semantic interpreter with object IDs, counts, negation, conditional scope and source span provenance. Candidate materialization needs a trusted, searchable or generative 3D asset catalog with calibrated bounds, active colliders, containers and affordances, and must refuse unsupported types. An independent judge should separately score source meaning, real native physical plausibility, source-respecting changes and observer-dependent prose. No general capable LLM comparison was run because shared Nitro/Thor inference and production workloads were occupied. No human literary-quality ratings or live PRSE deployment were invented.
