# The Crossing — modular PRSE browser game prototype

Live URL: `https://nitro.jonnyontherun.org/llm_game/` (the same historical Nitro game URL). Local source: `browser_physics_prototype/`; Apache continues to serve `/llm_game/` from `LLM_Game/web/`, whose entry page has an explicit same-origin base path to this prototype. Do not rewrite the Apache proxy or other live game/server services.

The current game is a short playable **exploration and repair** experiment, not a ragdoll game. Go left to find planks by the old beech, carry two of them, cross the fence, travel right to repair the missing footbridge deck, jump the obstructing crate if needed, and cross the stream. Experiment at the old mechanism by measuring a recurring hidden signal and trying to activate the lifting fence at a suitable time. The field journal preserves measurements. More geographic content is pre-generated ahead from validated semantic proposals, including one locally generated LLM scenery sample.

Manual controls: A/D or arrows (move), Space (jump), E (interact/pick up/inspect/repair/talk), F (experiment at mechanism), G (automated fence crossing), Escape (cancel), Enter (focus command input). Touchscreen buttons expose the main actions. The text input supports descriptions, interaction, measuring, timing, and semantic fence crossing. Saving and loading preserve physical state, coarse semantic state, journal, carried resources, bridge, and fence. Saved version 4 is used for the larger game; the implementation accepts older prototype save versions for compatibility.

Core architecture: `physics-core.js` owns authoritative game state, Rapier stepping and event ordering. `world-seed.js` stores the starting authored text/object facts. `semantic-world.js` owns persistent PRSE facts and coarsely simulated off-screen entities; `world-bridge.js` owns conversions into real Rapier bodies and back. `world-generator.js` owns bounded ahead-of-player proposal generation and validation; `llm-proposal-sample.js` records one validated local-LLM output for offline deployment, not live inference. `gameplay-rules.js`, `hidden-mechanism.js`, and `character-model.js` implement independent game-domain decisions. `side-view-renderer.js` only draws state and receives no authority to change the simulation. `text-adapter.js` exposes a separate headless text representation. `game.js` is only the browser/keyboard/touch adapter. `active-ragdoll.js` remains a separate optional doability lab; its controls are collapsed away from ordinary gameplay.

The renderer uses CC0 Kenney images from New Platformer Pack, with the existing local asset collection stored on the Raspberry Pi. The physics backend is pinned to the project's vendored Rapier 0.17.3; no CDN is needed while playing. See `PHYSICS_DOABILITY_2026-10-10.md` for measured feasibility, limitations, and unsolved requirements.

Tests: `./tests/run-game-tests.sh` runs deterministic physics, game, hidden-system, world, save/restore, renderer contract and performance studies without browsers. `tests/browser-smoke.py` runs the public browser E2E using an existing Nitro CDP host, creates its own temporary isolated browser context, and never closes unrelated tabs. `MOBILE=1` selects a 320 CSS-pixel emulated viewport. Use `GAME_URL='https://nitro.jonnyontherun.org/llm_game/'` to verify public delivery. This test utility uses the Nitro virtual environment Python packages and local Chromium CDP.
