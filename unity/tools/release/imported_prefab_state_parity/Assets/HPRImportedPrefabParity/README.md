# HPR Imported Prefab State Parity — private Unity Editor candidate

## What this does

This original, read-only Editor-only product captures **a bounded set of actual imported values** from prefabs loaded by the installed Unity Editor and compares two independently produced snapshots. It detects differences in GameObject hierarchy/names, active state, tag/layer/static flags, Transform values, Renderer/material and mesh/sprite references, MeshFilter shared meshes, TextMesh captions/font/size/color, Animator/controller/avatar references, Collider fields and Rigidbody settings. It also records all component type names but explicitly marks every other component type as not fully inspected. A covered value match does not imply all serialized object fields, custom MonoBehaviour data, shaders, animation playback, missing scene dependencies or Player builds match.

Unlike raw `.prefab` YAML diffing, it measures values of objects **loaded by each real Editor**, which may differ even when the exact original input bytes match. This distinguishes an actual cross-version import observation from source edits. Unity 7 changes are still announced/planned, not tested by this package; use installed Editors only.

## Documentation: prepare a real two-version prefab comparison

**What you need:** Two independently created, disposable Unity projects, built with different installed Unity Editor versions, containing the same original publisher asset package. Use actual tested `Assets/...` prefab paths visible in the Project window. Keep the exact original `.prefab` files and their `.meta` importer metadata unchanged and preserve a copy of the source release. This tool is Editor-only and never writes changes back to those prefabs.

**Coverage:** The inspector deliberately captures only listed types of GameObject and component fields. In addition, it recursively records original `Assets/...` source files referenced by the selected prefabs, including their Unity GUID, file SHA-256 and `.meta` SHA-256. Referenced Unity built-in or package-cache assets that cannot be verified as original files are listed separately and prevent an unqualified clean result. The recursive dependency scanner has a limit of five hundred twelve source dependencies and sixty-four unverified paths; the same sixty-four-mebibyte individual and two-hundred-fifty-six-mebibyte combined read bounds include these files. These checks do **not** cover all indirect importer platform settings or internal Library artifacts. If a package includes custom scripts, terrain, nested prefab internals, shaders, animation controllers, audio, physics interactions or third-party components not covered, a matching result is *not* certification of those fields. Uncovered component types are reported so they can be reviewed separately. A matching report is not an authorization to upgrade or overwrite a production project.

## First-use workflow

In two separate disposable Unity projects, **import the exact same original publisher `.unitypackage`** under two different supported Unity Editor versions. In each Editor choose **Tools > HPR > Imported Prefab State Parity**. Enter one or more exact prefab paths, such as `Assets/YourPublisherPack/Prefabs/Actor.prefab`, one per line (recommended) or separated with semicolons, up to twenty-four. The multiline field wraps long paths rather than hiding all but their beginning. Click **Scan imported prefabs (read only)**. The product uses public PrefabUtility.LoadPrefabContents and UnloadPrefabContents to inspect isolated prefab contents; it never saves, resaves, reimports, overwrites or changes source files. A missing prefab, missing script, unstable material/controller object reference, invalid path, file/read error, oversized input, too many values or cancellation produces an **INCOMPLETE** result, not a clean report.

The tool fingerprints each original `.prefab` file, its `.meta` file, and the original asset and importer `.meta` bytes of each file dependency Unity finds through the Asset Database, using SHA-256, up to sixty-four mebibytes per file and two hundred fifty-six mebibytes combined. It records at most twenty-five thousand covered values. Export only a successfully captured snapshot through **Export NEW prefab snapshot JSON**; existing files are never overwritten.

In either installed Editor choose **Choose first existing snapshot** and **Choose second existing snapshot**, then **Compare genuine imported prefab states**. If the source prefab or importer `.meta` files differ, the comparison says **SOURCE_BYTES_DIFFER_NO_EDITOR_INFERENCE**; it cannot attribute differing values to Unity import behavior. If the prefab sources match but referenced materials, meshes, scripts, or their importer `.meta` files differ, the result is **DEPENDENCY_INPUTS_DIFFER_NO_EDITOR_INFERENCE**. If dependency inputs supplied by Unity cannot be physically verified, such as built-in or package-cache inputs, the result is **DEPENDENCIES_UNVERIFIED_NO_EDITOR_INFERENCE** and must not be described as clean. Only if the verified prefab and dependency inputs agree can differing covered imported fields result in **REVIEW_IMPORTED_PREFAB_VALUE_DIFFERENCES**, showing added, removed and changed property keys. If the covered values match, the result is only **MATCHED_COVERED_IMPORTED_PREFAB_VALUES**. Always review the reported uncovered component types and test real prefabs, animations and Player builds separately.

## Troubleshooting and release acceptance

If the Editor reports **INCOMPLETE**, examine the failure message first. A path that does not exist must be replaced with an actual `Assets/... .prefab` location; imported model files such as `.fbx` are not themselves a `.prefab`. Missing-script components and references without a stable published Unity asset identity require manual review. Scans may also be incomplete because of the explicit asset and total data limits or user cancellation. Correct the specific input and run a new scan; never edit a JSON result to make it appear complete.

The current receipt format is **schema two**. Earlier schema-one snapshots contain no referenced-asset evidence and cannot safely be compared; recapture each original project with the new scanner. If two version reports say **SOURCE_BYTES_DIFFER_NO_EDITOR_INFERENCE**, verify that the *same* original prefab and `.meta` files were installed in both projects. A changed prefab source or importer setting invalidates a claim that a difference was caused by the Unity Editor version. If **DEPENDENCY_INPUTS_DIFFER_NO_EDITOR_INFERENCE** appears, compare the referenced source meshes, materials, scripts and `.meta` files, not just the prefab. If **DEPENDENCIES_UNVERIFIED_NO_EDITOR_INFERENCE** appears, resolve the reported built-in or package input before asserting full source equivalence; a loaded-value comparison may still be shown for manual inspection, but it is not a clean verdict. If all verifiable prefab and referenced-source inputs match but covered values differ, use **REVIEW_IMPORTED_PREFAB_VALUE_DIFFERENCES** as a pointer to specific properties that need additional manual and Player-build tests. A result of **MATCHED_COVERED_IMPORTED_PREFAB_VALUES** applies only to the declared covered fields; it cannot replace testing the asset's animations, materials, rendering and runtime behavior in both Editors.

The package has no runtime scene behavior, so it deliberately contains no decorative example scene. The official Asset Store Tools generic demonstration-scene check may report a warning for this Editor-only package. This warning is distinct from a C# compilation failure or a failure of the native scanning workflow and must not be represented as a passing validator check.

The package includes original source code only, runs offline, requires no runtime component, render pipeline or external account, and exports create-only JSON.
