# HPR Animation Event Receiver Audit — private Unity Editor product

**Original, private, NOT PUBLISHED.** A read-only diagnostic for a specific Unity animation problem: an animation clip calls `PlayFootstep`, but a saved character prefab with an Animator has no appropriate script receiver, or two identical events are hidden on one frame. It audits **existing clip Animation Events**, not a replacement event framework, not animation import/retargeting, and not an automatic repair script.

## Run a first scan

In Unity, import the complete `.unitypackage` and select **Tools > HPR > Animation Event Receiver Audit**. Optionally choose a folder inside **Assets** to limit the scan, or leave **Scan folder** empty to inspect all saved prefabs under Assets. Press **Scan saved prefab animation events**. The window reads saved prefab assets under `Assets`, their Animator controllers' referenced `AnimationClip`s, each clip's `AnimationEvent`s, and receiver `MonoBehaviour` methods attached to **the GameObject with that Animator**. It never changes clips, prefabs, controllers, scenes, Animator settings, imports or packages. The result distinguishes `FAIL`, `REVIEW`, `CLEAR_WITH_LIMITS` and `INCOMPLETE`.

Possible failures include an empty event name, no named method on the Animator GameObject and a named method with an unsupported return type, parameter count or parameter type. `REVIEW` includes overlapping animation markers at **exactly the same saved timestamp**, even if the function names differ, a script component that is missing from the Animator object, and event times outside the clip's duration. The tool does **not** automatically delete any event, add event methods, move a clip, or switch the active Animator. For a failed event, use Unity's standard Animation window and prefab Inspector to check the intended animation and correct the problem manually.

Each finding includes the saved prefab path, nested Animator object, clip path, event function and saved time, and a button to locate the prefab. **Export a NEW read-only JSON report** stores exact findings outside the Unity project. Existing files cannot be overwritten. Reports contain private project asset names/paths: inspect before sharing.

## Buyer workflow example

A saved character prefab uses an `AnimatorController` playing a clip `Walk`. The clip contains `Footstep` at zero point two seconds, and the same character GameObject has a script with `public void Footstep()`. The auditor finds a valid method. Rename the event in the clip to `FootstepRenamed` without changing the script, and the auditor flags a missing receiver. Add two events at precisely the same saved timestamp, for example `Footstep` and a stale `NewEvent`. The scanner warns about overlapping markers even though the functions differ, and independently reports the missing `NewEvent` receiver. Simultaneous events may be intentional. This is a diagnostic, not a guarantee the event actually fires when the character moves.

## Exact technical and commercial limits

The auditor inspects **saved prefabs under `Assets` with `Animator.runtimeAnimatorController`** only. It does not cover scene-only Animator GameObjects, old legacy `Animation` components, dynamically assigned controllers or receivers, prefabs in Registry packages, global resource loads, gameplay scripts added at runtime, unloaded Addressables or mismatched event payloads that require actual runtime testing. It also cannot guarantee that an event fires under state blending, frame skipping, animation speed differences or a disabled Animator. Methods are checked conservatively using reflection for a `void` method with zero or one supported argument: `int`, `float`, `string`, `AnimationEvent`, an `AnimationEventInfo` parameter where the installed Unity version supports it, or a `UnityEngine.Object`-derived reference. Event payload selection is not independently certified. A duplicate can be intentional; the program therefore reports `REVIEW`, not automatic failure. A clear local scan is **not** a clean Player build or customer compatibility guarantee.

The read-only scan is capped at fifteen hundred prefabs, six thousand referenced clips, twelve thousand animation events and three thousand findings. The scan visibly reports `INCOMPLETE` if a required asset cannot be loaded, the Editor is importing/compiling, or a limit is exceeded. File export is create-only and capped at two megabytes. Pure Editor-only C#, with no runtime library, external package, device telemetry, network, permission request or background service. Built-in, URP and HDRP use the same AnimationEvent data model, but this does not establish native product acceptance across all pipelines or Unity versions.
