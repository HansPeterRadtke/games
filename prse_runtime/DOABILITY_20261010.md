# PRSE: Headless simulation with a replaceable browser viewer (Nitro, 2026-10-10)

## Problem actually addressed

The game itself is **not** a browser program. The browser is merely one display/input adapter. The earlier prototype executed Rapier 3D physics and semantic changes inside browser JavaScript, which made recorded player events and server-side model inspection unavailable. The new design runs the same authoritative `GameCore` modules in a persistent Node.js service on Nitro, entirely without a DOM, graphics engine, or browser runtime. `headless-cli.mjs` also runs the same game rules in a terminal. The website at the unchanged `/llm_game/` URL loads `viewer.js` + `side-view-renderer.js` only and sends typed commands to the Nitro host.

The host runs the real Rapier 3D solver at 60 Hz. WebSocket pushes state to viewer(s) at up to 10 Hz with negotiated compression. No physics decisions or `GameCore.step` live in the browser. An independent Apache reverse proxy maps `https://nitro.jonnyontherun.org/llm_game_runtime/ws` to the loopback Node process; the original site URL remains unchanged. The headless service is under systemd, with no privilege escalation, local save directory and automatic restart.

## Persistence and observable evidence

Each anonymous demonstration session uses a random 128-bit token, lives in an authoritative Nitro GameCore instance, and persists its complete world snapshot to `/data/var/llm_game/prse_sessions/<token>.snapshot.json`. Structured NDJSON per-session logs include real client commands, canonical events (e.g., `candle_lit`), periodic world/position summaries, save/import/restart and model-request outcomes. Logs are local server files, not fake browser-console examples. Automatic log rotation is configured at 8MB, retaining seven backups. A disconnected viewer causes the host to stop movement and pause that session; reconnecting with the same token retrieves the world rather than restarting it. Browser-local v2-v5 snapshots can be explicitly imported into an existing server session after GameCore validation.

The independent `tests/headless-smoke.mjs` starts a local process and checks movement through real 3D physics, text narration, authoritative saving, browser-independent reload/reconnect, browser-local save import and rejection, and actual interaction event/logging. Real Chromium tests at the public URL verify the viewer does not load `game.js`, movement changes headless world state, Enter focuses the text input, server save survives reload, and a forced WebSocket disconnect reconnects without resetting the world. The 320px mobile layout tests pass without horizontal overflow or undersized controls.

## Live LLM doability

The client can explicitly request that the Nitro server send **current session state** to the already-running Jetson Qwen3.8-27B: current player position, physically visible entities and their conditions, player-known facts and recent visible game events. This is a real model request, not a pre-written description, but it is an **advisory output only**. It cannot directly change physical or semantic world truth.

The first live end-to-end probe successfully connected/imported a live scenario with a lit candle, but the model's output was truncated/malformed after about 46 seconds (`llm_error` record: `Unexpected end of JSON input`), so nothing was accepted as authoritative. Reducing prompt/context and simplifying the constrained schema yielded a second end-to-end **successful** test: 35.016 seconds, 86 predicted tokens. The Jetson model accurately reported that a shelter had a *lit candle*, a water jug and a note, with the bridge unrepaired and fence closed, without inventing a paper fire. A `llm_request` event and the complete `llm_response` data were durably recorded under the session token on Nitro.

**Important:** The model is **not** continuously observing the world, is **not** an NPC mind running each physics tick, and does **not** autonomously decide world consequences yet. It sees a scoped structured snapshot only when explicitly requested, which proves integration without claiming real-time comprehension. Its response takes tens of seconds and can still be inconsistent. There is one global in-flight model request and cooldown to avoid unbounded GPU load from the public demonstration.

## Trade-offs and open questions

The viewer now needs connectivity to the Nitro simulation server; it preserves state through interruptions but does not continue computing physics offline. The earlier offline-in-browser approach is retained only as a separate experimental baseline. Weak-network bandwidth, input latency and the quality of 10Hz presentation need actual mobile field measurements. Future native desktop/Android clients, Godot/Unity renderers, a true portable engine abstraction and native 3D perspective are separate tested adapters rather than assumed completed features. The source code remains in the historic `browser_physics_prototype/` folder until an atomic refactor can relocate it without breaking tests; this historical filename is not the engine architecture. The public anonymous token model must not be reused for sensitive or production multiplayer without user authentication, authorization, quotas, and auditing. Long-term LLM generation and physically causal semantic reasoning remain research tasks.
