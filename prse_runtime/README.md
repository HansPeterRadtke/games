# PRSE game engine — authoritative headless host

**The browser is only a view.** The actual simulation is a replaceable host process and the game-domain/physics code is independent of DOM, Canvas and browser lifecycles. At present the historical module folder is `../browser_physics_prototype/`; renaming this folder must be a separate tested migration because existing tests and imports depend on it. The backend contains `GameCore`, Rapier 3D, `SemanticWorld`, `WorldBridge`, player capabilities, causal simulation, event generation and procedural worlds. `headless-cli.mjs` runs the same GameCore with a text adapter without starting Chrome or a web server.

This directory provides a *Node.js host adapter*, not a different set of game rules. The running Nitro process is `/usr/bin/node .../prse_runtime/server.mjs`, supervised by `prse-engine.service`, listening only at `127.0.0.1:18764`. A dedicated Apache proxy exposes HTTPS/WSS under `/llm_game_runtime/`. The original public URL `/llm_game/` loads `viewer.js` and `side-view-renderer.js` with static CC0 images; neither module imports nor steps GameCore. A different native CLI, Unity, Godot or another 3D renderer could consume the same game-domain model through its own suitable bridge. True cross-engine backend portability is not yet demonstrated.

The host owns 60Hz physics steps, canonical commands/events, world state and server snapshots. It pushes compacted WebSocket JSON state at 10Hz to a browser presentation adapter; per-message DEFLATE is negotiated where available. Interactions run on the server. Every player session gets an unguessable 128-bit session token stored in the browser localStorage, and the authoritative state persists in Nitro's `/data/var/llm_game/prse_sessions/<token>.snapshot.json`. Important commands/events, diagnostics, model requests/responses and periodic player/semantic summaries are recorded in per-session JSONL (`.events.ndjson`). A disconnected session stops running but retains its state. The browser reconnects with the same token and resumes; no server account or Google authentication is required for this experimental project. Sessions are private by token, not protected by a full account access-control system.

The optional **Ask Jetson LLM** action is handled *server-side* using a perception-filtered current structured snapshot (player, visible entities, known facts, recent visible events). It is strictly advisory: generated text cannot replace the physics result. The model is not called continuously, and a stalled request times out without blocking simulation. Model latency, output quality, and long-term coherent narrative generation remain open feasibility questions. The user can inspect model wording and its uncertainty in the browser; structured request/response records are written to Nitro's session logs.

## Launch and tests

On Nitro: `systemctl status prse-engine.service --no-pager`. To inspect without a browser: `node /data/src/github/games/prse_runtime/headless-cli.mjs --steps=180 --command=look`. Full server-only acceptance: `node /data/src/github/games/prse_runtime/tests/headless-smoke.mjs` (starts a private temporary engine on a random port, checks command execution, persistence, reconnect and importing an old local save). Public viewer acceptance: `PRSE_BROWSER_URL=https://nitro.jonnyontherun.org/llm_game/ /data/venv/bin/python /data/src/github/games/prse_runtime/tests/browser-remote-smoke.py`; add `MOBILE=1` for mobile layout and touch-size checks. The existing game rules also retain their headless regression suite in `../browser_physics_prototype/tests/run-game-tests.sh`.

The real service configuration is in `deploy/prse-engine.service`, and Apache's dedicated proxy configuration is `deploy/prse-runtime.apache.conf`. The installed copies are `/etc/systemd/system/prse-engine.service` and `/etc/apache2/conf-available/prse-runtime.conf`. Both can be updated without changing the legacy LLM_Game speech service or Apache's `/llm_game/` static alias. The previous HTML page is backed up in `/data/var/backups/game-web/index-before-headless-20261010.html`, and the legacy browser-only experiment remains available separately as `physics-prototype/index.html` for compatibility with older saves.

## Known trade-offs

The headless simulation is now observable, persistent and independent of browser rendering, but the networked viewer is not fully offline-capable: during an interruption it shows the last rendered state, reconnects automatically and resumes Nitro's state. Serving visuals from the same host avoids downloading Rapier to weak clients; keeping the whole simulation client-local would make offline use easier but prevents reliable server-side recording and LLM integration. Native 3D presentation and native backend compilation are later adapters, not features already implemented. This demonstration exposes a public anonymous game endpoint; don't reuse its capability-token session model for sensitive/multiplayer production without authentication and authorization. The session logs must be rotated/retained appropriately and not filled with user secrets.
